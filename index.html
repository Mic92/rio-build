rio-build

Distributed Nix build farm. Clients speak the standard Nix worker protocol over SSH; everything behind the gateway is gRPC.

nix client

Unmodified Nix. --store ssh-ng://rio or remote-builder hook.

rio-gateway

SSH server. Translates worker-protocol opcodes → gRPC. Stateless, multi-replica.

rio-scheduler

DAG-aware, critical-path scheduling. Streams work to builders. Leader-elected.

rio-builder

Executes derivations in a Nix sandbox. Lazy /nix/store via FUSE + local SSD cache.

rio-store

Chunked content-addressed store. FastCDC + BLAKE3 dedup. Server-side chunking.

PostgreSQL

Single shared DB. Build state, store metadata, tenants. One migration set.

S3

Deduplicated chunk blobs. Inline blobs for small NARs (<256 KiB).

Scheduler — derivation lifecycle

stateDiagram-v2

  running --> failed : retriable

  poisoned --> created : 24h TTL
  completed --> [*]
  poisoned --> [*]

Single in-memory DAG actor serializes all transitions; multi-build merge dedupes shared subgraphs. Ready nodes ranked by critical-path length × duration estimate × tenant priority. State persisted to PostgreSQL for leader failover.

Store — upload path (PutPath)

flowchart LR
  A["NAR stream in"] --> B["buffer + SHA-256 verify"]
  B --> C["FastCDC chunk\n+ BLAKE3 each"]
  C --> D["PG txn:\nmanifest + refcount UPSERT"]
  D --> E{"chunk new?"}
  E -->|yes| F["S3 PUT ×8 parallel"]
  E -->|no| G["dedup — skip"]
  F --> H["PG: mark complete\n+ narinfo + refs"]
  G --> H

Chunking + hashing is server-side — gateway and builders just stream bytes. Write-ahead manifest in PG protects chunks from GC mid-upload. In-flight NAR bytes capped at 32 GiB (semaphore → gRPC backpressure, no OOM).

Who moves bytes where

PathRouteCPU heavy stepWhere it runs
Source uploadclient → gateway → storechunk + hashrio-store
Build inputsstore → builder (FUSE, lazy)NAR reassemblyrio-store
Build outputsbuilder → store (direct)chunk + hashrio-store
Result downloadstore → gateway → clientNAR reassemblyrio-store

Yes — rio-store is in the path of every byte. Gateway only proxies the client-facing legs (no chunking/hashing on it). Build I/O between builders and store never touches the gateway. ssh-ng has no payload compression; only ssh transport-level zlib.
